# Phase 05.1 — UI Design Contract: Visual Experience Overhaul

> Visual and interaction contract for frontend phases. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> This is a **visual overhaul** of an existing working app. All decisions operate on top of the current CSS Modules + custom properties foundation. No new game mechanics. No new data flows. The contract below describes what the upgraded UI must look and behave like.

|-------|-------|-------|

### World-State Atmosphere Tint (D-03)

The ambient background gradient shifts with world state. This is driven by CSS custom properties written via JavaScript (inline style on a wrapper element, not on `:root`).

**Implementation approach:** `App.jsx` (or a layout wrapper) writes `--atmosphere-warmth` as an inline CSS variable. Value range: 0.0 (all meters at 0) to 1.0 (all meters at 100). Computed as `(trust + courage + solidarity + awareness) / 400`.

| `--atmosphere-warmth` | Gradient center color |
|---|---|
| 1.0 (all high) | `rgba(245, 158, 11, 0.20)` warm amber |
| 0.5 (neutral) | `rgba(245, 158, 11, 0.10)` dim amber |
| 0.0 (all low) | `rgba(59, 130, 246, 0.08)` cold blue wash |

Interpolation: linear mix, handled by the ambient gradient component/pseudo-element.

### Accent Reserved For

Accent (`#f59e0b`) is used **only** on:
- Primary CTA buttons (solid fill: Join Session, Start Game, Share Reflection)
- Selected/locked choice button — glow border ring (`box-shadow: 0 0 0 2px var(--accent), 0 0 20px var(--glow-amber-strong)`)
- Framework name display (FrameworkProfile, FrameworkLabel text)
- Room code large display (Host lobby)
- Meter fill gradient — amber anchor stop (high value end)
- Framework tag pill background tint (existing `--accent-bg`)
- Active round selector button (HostSetup)
- Submitted counter number (Play.jsx `.submittedNumber`)

Accent is NOT used on:
- Body text, muted labels, metadata
- Non-selected choice buttons
- Glass card borders (use `--glass-border` instead)
- Borders between sections (use `--glass-border-subtle`)

## Glass-Morphism Surface Spec (D-07)

All cards, panels, and content containers adopt glass-morphism. The flat `background: var(--bg-surface); border: 1px solid #2e303a` pattern is replaced.

**Glass surface recipe:**

```css
background: var(--glass-bg);          /* rgba(18, 18, 30, 0.65) */
backdrop-filter: blur(var(--blur-glass));  /* 16px */
-webkit-backdrop-filter: blur(var(--blur-glass));
border: 1px solid var(--glass-border);    /* rgba(245,158,11, 0.18) */
border-radius: 12px;
box-shadow:
  0 4px 24px rgba(0, 0, 0, 0.4),
  inset 0 1px 0 rgba(255, 255, 255, 0.04);
```

**Apply glass recipe to:**
- ScenarioCard (`.card`)
- ConsequenceReveal container
- ContentNote container
- FrameworkProfile section cards (`.sectionCard`, `.conflictSection`)
- WorldStatePanel (host side panel)
- VoteTally container
- PlayerRoster card (host lobby)
- Any new `section` wrappers in Landing.jsx

**Do NOT apply glass to:**
- Full-page backgrounds (`.page` — keeps `--bg` solid)
- MeterBar track (stays opaque `#2e303a`)
- Input fields (keep `--bg-surface` solid for readability)
- Timer display text (no container treatment needed)

## Ambient Background (D-02)

A single slow-moving radial gradient that drifts behind all page content. The screen is never static.

**Implementation:** A `<div aria-hidden="true">` absolutely positioned in each page layout (or in `App.jsx` as a fixed layer behind the router outlet). Animated with a CSS `@keyframes` that shifts gradient position over 12–16 seconds, infinite, alternating.

```css
/* Ambient gradient keyframe — goes in index.css */
@keyframes ambientDrift {
  0%   { background-position: 20% 40%; }
  33%  { background-position: 60% 20%; }
  66%  { background-position: 40% 70%; }
  100% { background-position: 20% 40%; }
}

.ambientLayer {
  position: fixed;
  inset: 0;
  z-index: 0;
  pointer-events: none;
  background:
    radial-gradient(ellipse 80% 60% at var(--gradient-x, 30%) var(--gradient-y, 40%),
      var(--glow-amber) 0%,
      transparent 60%);
  animation: ambientDrift 14s ease-in-out infinite;
}
```

All page content sits on `z-index: 1` or higher relative to this layer. `position: relative` on content containers is sufficient.

**Reduced motion:** `animation-duration: 0.01ms !important` from the global guard kills the drift. The gradient still renders at its 0% position — a static warm glow. This is acceptable; the screen does not go cold.

## Transitions & Motion (D-10, D-11, D-12)

### Dependency

`framer-motion@11` — install before implementing any animated transitions.

### Page Transitions (Framer Motion — AnimatePresence)

Wrap the route outlet in `App.jsx` with `<AnimatePresence mode="wait">`. Each top-level page component (`Landing`, `Host`, `HostSetup`, `Play`) gets Framer Motion variants.

**Standard page enter/exit:**

```js
const pageVariants = {
  initial: { opacity: 0 },
  animate: { opacity: 1, transition: { duration: 0.4, ease: 'easeOut' } },
  exit:    { opacity: 0, transition: { duration: 0.25, ease: 'easeIn' } }
}
```

Use `<motion.div variants={pageVariants} initial="initial" animate="animate" exit="exit">` as the outermost wrapper inside each page component.

### Round-to-Round Transition (D-11 — Cinematic Fade-Through)

Not a page navigation — happens within `Play.jsx` as round status changes. Use Framer Motion `AnimatePresence` wrapping the game content area, with a black interstitial hold.

**Sequence:**
1. Current content fades to opacity 0 over 300ms
2. Black hold: 350ms (rendered as a `<motion.div>` with `background: #000`, full-screen, z-index above content)
3. New content fades in from opacity 0 over 400ms

```js
// Round transition variant
const roundTransition = {
  exit:    { opacity: 0, transition: { duration: 0.3 } },
  initial: { opacity: 0 },
  animate: { opacity: 1, transition: { duration: 0.4, delay: 0.35 } }
}
```

The black hold (`0.35s delay` on animate) is the "scene change feel." Do not use a slide, crossfade, or blur — fade-through only per D-11.

### End Screen Staggered Reveal (D-12 — FrameworkProfile)

Replace the current CSS `animation-delay` pattern with Framer Motion stagger. Wrap each section in `<motion.div>` with `variants`. Parent uses `staggerChildren`.

**Stagger config:**
```js
const containerVariants = {
  hidden: {},
  show: { transition: { staggerChildren: 0.25 } }
}
const sectionVariants = {
  hidden:  { opacity: 0, y: 12 },
  show:    { opacity: 1, y: 0, transition: { duration: 0.5, ease: 'easeOut' } }
}
```

**Section reveal order:**
1. Dominant framework card — delay 0 (first child)
2. Conflict map (if present) — delay 0.25s
3. Least-used framework prompt — delay 0.5s
4. Choice log — delay 0.75s
5. Reflection input (Round 6) — delay 1.0s

### Reduced Motion

Framer Motion respects `prefers-reduced-motion` via `useReducedMotion()` hook. Apply at the top of each component using Framer Motion:

```js
import { useReducedMotion } from 'framer-motion'
const shouldReduce = useReducedMotion()
// Pass instant duration when true
const transition = shouldReduce ? { duration: 0 } : { duration: 0.4 }
```

The global CSS guard in `index.css` also continues to apply — belt and suspenders.

## Constraints Carried Forward

From upstream decisions and codebase audit:

1. No TypeScript — all implementation in plain JavaScript (.jsx)
2. No Tailwind, no shadcn, no component library — all CSS Modules
3. `backdrop-filter: blur()` requires content to sit above a non-opaque layer — the ambient gradient provides this; solid `--bg` fallback for browsers without backdrop-filter support is acceptable (graceful degradation)
4. Reduced-motion guard in `index.css` kills all CSS animations; Framer Motion's `useReducedMotion()` kills JS-driven animations — both must be applied
5. Mobile: player view (Play.jsx) must remain thumb-reachable; glass-morphism and font size changes must be tested at 375px viewport width
6. Framer Motion must NOT be used on MeterBar fills — those run on Supabase real-time updates and must stay pure CSS transitions to avoid jank
7. Three.js city: still deferred to v2. CityPlaceholder.jsx receives glass treatment only
