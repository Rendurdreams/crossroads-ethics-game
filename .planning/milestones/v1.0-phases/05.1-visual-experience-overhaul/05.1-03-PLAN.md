    2. **Round transitions (D-11):** The active round view and round_complete view should use `AnimatePresence` to fade through black when the round status changes. Add a second `AnimatePresence mode="wait"` inside the game content area:
       ```jsx
       import { motion, AnimatePresence, useReducedMotion } from 'framer-motion'

       const roundTransition = {
         exit:    { opacity: 0, transition: { duration: 0.3 } },
         initial: { opacity: 0 },
         animate: { opacity: 1, transition: { duration: 0.4, delay: 0.35 } }
       }
       ```

       In the active round / round_complete section of the render, wrap the game content in:
       ```jsx
       <AnimatePresence mode="wait">
         <motion.div
           key={`round-${session.current_round}-${session.status}`}
           variants={shouldReduce ? { initial: {}, animate: {}, exit: {} } : roundTransition}
           initial="initial"
           animate="animate"
           exit="exit"
         >
           {/* scenario card or consequence reveal content */}
         </motion.div>
       </AnimatePresence>
       ```

       **CRITICAL:** The key MUST include BOTH `current_round` AND `status` so the transition fires when the round closes (status changes from active to round_complete), not only when the round number increments. Per RESEARCH.md Pitfall 5.

       Apply this AnimatePresence around the game content area in the active and round_complete branches. The exact placement: inside the `.gameContent` div, wrapping the content that changes between rounds. The `.gameContent` wrapper stays static, the inner content animates.

    3. **Atmosphere tint (D-03):** Same as Host.jsx. Compute warmth from `session?.world_state` and write `style={{ '--atmosphere-warmth': warmth }}` on page-level wrappers that have worldState access. For lobby and loading views (no worldState), use default 0.5.

    4. **Reflection section in finished view:** The `.reflectionSection` in Play.module.css had its CSS animation-delay removed in Plan 02. Add a simple Framer Motion fade-in for the reflection section in the finished view:

       ```jsx
       <motion.div
         className={styles.reflectionSection}
         initial={shouldReduce ? {} : { opacity: 0, y: 12 }}
         animate={shouldReduce ? {} : { opacity: 1, y: 0 }}
         transition={shouldReduce ? { duration: 0 } : { duration: 0.5, delay: 0.8 }}
       >
         {/* reflection content */}
       </motion.div>
       ```

    **Important implementation notes:**
    - Do NOT use Framer Motion on MeterBar fills (per RESEARCH.md anti-patterns). MeterBar stays pure CSS transitions.
    - Do NOT break the existing Supabase subscription useEffects or state management logic. Only change the JSX return sections.
    - Keep all existing className assignments. motion.div accepts className just like div.
    - For return paths that render minimal content (loading, waiting), a simple motion.div page wrapper is fine — no AnimatePresence needed for those.
