  <action>
    Restructure App.jsx per RESEARCH.md Pattern 1 (Ambient Layer) and Pattern 3 (Page Transitions).

    **Critical architectural change:** Split `App` into two components because `useLocation()` must be called inside `BrowserRouter`, not at the same level (RESEARCH.md Pitfall 2).

    Replace the entire App.jsx with:
    ```jsx
    import { BrowserRouter, Routes, Route, useLocation } from 'react-router-dom'
    import { AnimatePresence } from 'framer-motion'
    import Landing from './pages/Landing.jsx'
    import HostSetup from './pages/HostSetup.jsx'
    import Host from './pages/Host.jsx'
    import Play from './pages/Play.jsx'

    function AppRoutes() {
      const location = useLocation()
      return (
        <>
          <div aria-hidden="true" className="ambientLayer" />
          <AnimatePresence mode="wait">
            <Routes location={location} key={location.pathname}>
              <Route path="/" element={<Landing />} />
              <Route path="/host-setup/:sessionId" element={<HostSetup />} />
              <Route path="/host/:sessionId" element={<Host />} />
              <Route path="/play/:sessionId" element={<Play />} />
            </Routes>
          </AnimatePresence>
        </>
      )
    }

    function App() {
      return (
        <BrowserRouter>
          <AppRoutes />
        </BrowserRouter>
      )
    }

    export default App
    ```

    Key details:
    - `ambientLayer` div uses global class name (defined in index.css, not a CSS Module) — per RESEARCH.md, this is the one exception to the CSS Modules pattern
    - `aria-hidden="true"` for accessibility (decorative element)
    - `AnimatePresence mode="wait"` ensures exit animation completes before enter fires (per D-11 cinematic fade-through)
    - `location={location} key={location.pathname}` on Routes — required for AnimatePresence to detect route changes
    - `useLocation()` called inside `AppRoutes` which is a child of `BrowserRouter` — avoids the "useLocation outside Router" error
  </action>
