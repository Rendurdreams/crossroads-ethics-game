## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline badge padding, margin-bottom between label and content |
| sm | 8px | Compact stacks (label → content), gap between roster chips, QR code margin-top |
| md | 16px | Default element spacing, form field margin-bottom, section internal gaps |
| lg | 24px | Page edge padding, card internal padding, section-to-section spacing |
| xl | 32px | Major block separation (form section to form section), FrameworkProfile card gap |
| 2xl | 48px | Page top breathing room on HostSetup, bottom safe-area buffer on Play |
| 3xl | 64px | Not used in Phase 5 scope |

Exceptions:
- Touch targets: all interactive elements (buttons, choice buttons) enforce `min-height: 44px` regardless of content height. This is a hard mobile requirement, not a spacing token (POLISH-01).
- Room code display on HostSetup: `clamp(72px, 12vw, 120px)` — typographic sizing not spacing token.
- QR code: fixed at 180×180px per D-08.

Source: Measured from `Landing.module.css`, `Play.module.css`, `HostSetup.module.css`, `ScenarioCard.module.css`, `FrameworkProfile.module.css`.

## Typography

| Role | Size | Weight | Line Height | Font | Usage |
|------|------|--------|-------------|------|-------|
| Body | 16px | 400 | 1.5 | sans (Inter) | Default prose, waiting text, instructions, textarea input |
| Label / Meta | 14px | 400 | 1.4 | sans | Uppercase tracking labels, round labels, choice log rows, error messages, muted counters |
| UI Heading | 20–28px | 600 | 1.2 | sans | Page headings (HostSetup 28px, section headings 20px), framework name in profile card |
| Scenario / Serif Body | 18px | 400 | 1.65 | serif (Georgia) | Scenario card body text, FrameworkProfile explanation paragraph, reflection question |

Two weights in use: 400 (regular) and 600 (semibold). No other weights.
Two families in use: `var(--sans)` and `var(--serif)`. No other families.

Source: `src/index.css` font declaration, `ScenarioCard.module.css`, `FrameworkProfile.module.css`, `HostSetup.module.css`, `Play.module.css`.

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0a0a14` (`--bg`) | Page background, full-bleed surfaces |
| Secondary (30%) | `#12121e` (`--bg-surface`) | Cards, input backgrounds, choice buttons, textarea, framework profile cards |
| Accent (10%) | `#f59e0b` (`--accent`) | Reserved elements listed below |
| Accent hover | `#d97706` (`--accent-hover`) | Hover state on accent buttons only |
| Accent bg | `rgba(245,158,11,0.1)` (`--accent-bg`) | Locked choice button fill, framework tag badge background |
| Destructive | `#ef4444` (`--danger`) | Error messages only |

Accent (`#f59e0b`) reserved for:
- Room code display (large number on HostSetup)
- QR code foreground color (per D-08: `fgColor="#f5f0e8"` cream variant — see note below)
- Primary CTA button background (Create Game, Join, Open Lobby, Submit Reflection)
- Active round selector button background
- Locked choice button border
- Framework tag text and badge
- Submitted counter number highlight in Play.jsx
- "Starting..." and "Game complete" state text on player lobby
- Focus ring on text inputs (`outline: 2px solid var(--accent)`)

QR code color note: D-08 specifies `bgColor="#12121e"` and `fgColor="#f5f0e8"` (light cream). The cream `#f5f0e8` is used exclusively for the QR code foreground — it is not a general UI color token. It matches the editorial paper-white feel without being stark white against the dark background.

Border color for cards and inputs: `#2e303a` — a fixed literal used throughout (not a CSS variable). This is the established pattern; do not introduce a new variable for it in Phase 5.

Text colors:
- `#f5f5f5` (`--text-h`) — headings and high-emphasis text
- `#e5e5e5` (`--text`) — body text
- `#6b7280` (`--text-muted`) — muted labels, helper text, waiting states

Source: `src/index.css` root variables, confirmed across all module CSS files.

## Mobile Audit Contract (POLISH-01)

Audit target: player-facing pages at 390px viewport width (iPhone 14 baseline).

Pages in scope:
- `src/pages/Landing.jsx` — join flow
- `src/pages/Play.jsx` — game rounds, consequence reveal, reflection input, profile reveal
- `src/components/FrameworkProfile.jsx` — end screen

Pages explicitly out of scope: `Host.jsx`, `HostSetup.jsx` (desktop-only by design).

Pass criteria (from D-11, POLISH-01):

| Criterion | Measurement |
|-----------|-------------|
| No horizontal scroll | `body` width does not exceed `100vw` at 390px; no element with `overflow-x: visible` wider than viewport |
| Buttons reachable with thumbs | All interactive elements: `min-height: 44px`, no element in top 20px dead zone, adequate tap spacing |
| Scenario text readable without zooming | Scenario body font is 18px serif at 1.65 line-height — must not be overridden to smaller on mobile |
| Choice buttons full-width | `width: 100%` maintained — already in spec, verify not broken |
| Input fields full-width | `width: 100%` with `box-sizing: border-box` — already in spec, verify |
| Reflection textarea usable | `min-height: 120px`, no zoom-trigger (font-size 16px — already correct) |

Fixes allowed: Any CSS change that brings the page within POLISH-01 pass criteria.
Fixes not in scope: Aesthetic improvements, spacing rhythm, font refinements — these are v2 per D-12.

**Zoom-trigger guard:** iOS Safari zooms on input focus when `font-size < 16px`. All inputs and textareas in scope already use `font-size: 16px` or `1rem`. Verify no mobile override reduces this.

## Load Test Script Contract (scripts/load-test.js)

This is a CLI script — no UI. No visual contract applies.

Output format contract: plain text to stdout.

```
[LOAD TEST] Opening 25 subscriptions to session {id}...
[OK] All 25 channels active.
[TEST] Writing 10 choice inserts...
[RESULT] 25/25 channels received all 10 events within 2000ms — PASS
```

On failure:
```
[RESULT] 23/25 channels received all events — FAIL (2 channels dropped events)
```

No UI component needed. Script lives at `scripts/load-test.js`, not in `src/`.

## Interaction States — QR Code Component

The QR code is a display-only element. No interaction states beyond:

- **Before session created:** Component not rendered (no room code available).
- **After session created:** QR code renders at full opacity.
- **Print/screen-share:** QR code is SVG — scales losslessly at any projection size.
- **No loading state:** QR code renders synchronously from `qrcode.react`.
