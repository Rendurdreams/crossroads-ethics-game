## Spacing Scale

All values are multiples of 4. Drawn from existing usage across `Play.module.css`, `Landing.module.css`, and `ScenarioCard.module.css`.

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Rank badge internal padding, inline icon gap |
| sm | 8px | Gap between rank badge and value label, form element spacing |
| md | 16px | Gap between value cards, section heading margin, inner card padding |
| lg | 24px | Page horizontal padding, section-to-section gap, card padding |
| xl | 32px | Content wrapper vertical padding start |
| 2xl | 48px | Page bottom padding, major section breaks |
| 3xl | 64px | Not used on mobile — omit |

Exceptions:
- Value card minimum tap height: 44px (accessibility — matches `ScenarioCard.choiceBtn` min-height)
- Stance button minimum tap height: 44px (same source)
- Content max-width: 480px (matches `.gameContent` in `Play.module.css`)

Source: Existing CSS Modules measurements + WCAG 2.5.5 touch target standard.

## Component Inventory

Components for `Baseline.jsx` and `Baseline.module.css`. All are new; no existing component is modified except the routing additions to `App.jsx` and the navigation change in `Landing.jsx`.

### Value Card (new — `Baseline.module.css`)

States:

| State | Visual |
|-------|--------|
| Unranked (available) | `--glass-bg` background, `--glass-border-subtle` border, `--text` label color. Hover: `--glass-border` border, subtle amber box-shadow (matching `.choiceBtn:hover`). |
| Ranked (tapped) | `--accent-bg` background (`rgba(245,158,11,0.12)`), `--glass-border` border with amber glow box-shadow. Rank badge visible (amber circle, `--bg` text, 13px bold). "tap to undo" hint at 13px muted. |
| All-ranked (all 5 done) | Remaining unranked cards not applicable — all 5 will be ranked when complete. |

Layout: Single column, stacked. Each card is full-width within the 480px max-width content wrapper. Minimum height 44px. Cards arranged top-to-bottom — unambiguous scan order.

Source: CONTEXT.md D-04, D-05; RESEARCH.md §Open Questions answers (single column, number badge).

Rank badge: Plain number (1–5) in a small amber circle. 20px diameter. No ordinals ("1st"). Positioned top-left inside the card, overlapping slightly. Label: 13px bold `--bg` on `--accent` background.

Source: RESEARCH.md §Open Questions (rank badge recommendation).

Tap-to-undo semantics: Tapping a ranked card clears it AND all cards ranked after it. Example: tapping rank-2 card makes ranks 2–5 unranked again. This keeps the array always a valid prefix. The "tap to undo" hint on each ranked card communicates this.

Source: RESEARCH.md §Pitfall 5, §Tap-to-Rank Interaction Pattern.

### Stance Buttons (reuse — `ScenarioCard.module.css`)

Reuse `.choiceBtn`, `.choiceLocked`, `.choiceDimmed`, `.choiceNumeral` exactly. No visual change.

Roman numeral prefix: I / II / III (amber, 13px bold) before each option label.

Selected state: `.choiceLocked` — amber border + glow + `rgba(245,158,11,0.12)` background.
Unselected after selection: `.choiceDimmed` — 0.3 opacity, grayscale filter.

One question visible at a time? No — both stance questions are present on the page simultaneously. Both are rendered but question 2 is visually disabled (pointer-events none, 0.4 opacity) until question 1 has a selection. This avoids hidden content and allows players to see what is coming.

Source: CONTEXT.md D-08; RESEARCH.md §Pitfall 4 (stance questions after ranking); RESEARCH.md §Stance Question Pattern.

### Progress Separator (new — `Baseline.module.css`)

Between value ranking section and stance questions section: a horizontal amber gradient rule — matching the `.divider` pattern in `Landing.module.css`. Label text centered above the rule: "Your stance" at 13px bold `--sans`, uppercase, letter-spacing 0.1em, `--text-muted` color.

No step dots, no numbered indicators. The separator + section label is sufficient for a two-section flow.

Source: CONTEXT.md (Claude's Discretion — progress indicator style); `Landing.module.css .divider`.

### Submit Button (new — `Baseline.module.css`)

Full-width CTA. Matches `Landing.module.css .btn` exactly:
- `linear-gradient(135deg, #f59e0b 0%, #d97706 100%)` background
- `#0a0a14` text color (dark on amber)
- 14px padding, 44px min-height, 8px border-radius
- Disabled state: 0.5 opacity, `cursor: not-allowed`
- Loading state (during Supabase write): button disabled + label changes to "Sealing your counsel…"

Enabled condition: `rankedValues.length === 5 && Object.keys(stances).length === 2`.

Source: `Landing.module.css .btn`; RESEARCH.md §Submit handler.

### Stance Section Gate

The entire stance section (both questions + their container) renders at 0.4 opacity with `pointer-events: none` until `rankedValues.length === 5`. When all 5 are ranked, a CSS class swap removes the disabled styles with a 300ms `opacity` transition.

This is a single-page scrollable layout — no pagination. Players scroll down to reach stances. The disabled state signals "finish ranking first" without hiding the stances entirely.

Source: RESEARCH.md §Open Questions #1 (single-page recommendation), §Pitfall 4.

## Interaction States

| Interaction | Trigger | Visual Response |
|-------------|---------|-----------------|
| Value card tap (unranked) | Player taps available card | Card transitions to ranked state (amber border, glow, rank badge appears, "tap to undo" appears). CSS `transition: border-color 200ms ease, box-shadow 200ms ease`. Scale pulse: `transform: scale(1.02)` for 120ms then return. |
| Value card tap (ranked) | Player taps ranked card | Card and all higher-ranked cards revert to unranked. CSS transition same as above. No confirmation dialog. |
| All 5 ranked | `rankedValues.length === 5` | Stance section opacity transitions from 0.4 to 1.0 over 300ms. `pointer-events` restored. Ranking instruction micro-copy fades to 0.4 opacity. |
| Stance button tap | Player taps one of 3 options | Selected button: `.choiceLocked` styles. Other two: `.choiceDimmed`. Cannot change selection once made (consistent with decree-tile pattern — matches `ScenarioCard` lock behavior). |
| All stances answered | Both `lie_to_protect` and `ends_justify` set | Submit CTA transitions from disabled to enabled — opacity 0.5 → 1.0, `cursor: not-allowed` → `cursor: pointer`. |
| Submit tap | Player taps "Enter the Council" | Button label → "Sealing your counsel…", disabled, no spinner needed. Supabase UPDATE fires. On success: navigate to `/play/:sessionId`. |
| Submit error | Supabase UPDATE returns error | Error copy replaces loading label. Button re-enabled for retry. localStorage state preserved. |
| Page refresh mid-flow | Browser refresh | Mount restore reads `baseline_ranked` and `baseline_stances` from localStorage and re-hydrates state exactly. Player sees their progress intact. |
| Already-completed baseline | `player.moral_values !== null` on mount | Immediate `navigate('/play/:sessionId', { replace: true })` — player never sees baseline page again. |

Source: CONTEXT.md D-04, D-05; RESEARCH.md §Pitfall 1–5, §Tap-to-Rank Interaction Pattern.

## Animation Contract

| Element | Animation | Spec |
|---------|-----------|------|
| Page enter | Framer Motion `pageVariants` | `opacity: 0 → 1`, duration 400ms, `easeOut` — copy exactly from Landing.jsx |
| Page exit | Framer Motion `pageVariants` | `opacity: 1 → 0`, duration 250ms, `easeIn` |
| Value card ranked state | CSS transition | `border-color 200ms ease, box-shadow 200ms ease, transform 100ms ease` |
| Value card scale pulse on tap | CSS keyframe | `scale(1.02)` for 120ms, return to `scale(1)` — one-shot, no loop |
| Stance section unlock | CSS transition | `opacity 0.4 → 1.0` over 300ms, no transform |
| Submit CTA enable | CSS transition | `opacity 0.5 → 1.0` over 200ms |
| Reduced-motion guard | Global `index.css` rule | All animations collapse to 0.01ms automatically — no per-component override needed |

No Framer Motion used for individual card/button animations — CSS transitions only. Framer Motion used only for page-level enter/exit.

Source: RESEARCH.md §Framer Motion page transition; `src/index.css` `@media (prefers-reduced-motion)`.

## Accessibility Contract

| Requirement | Implementation |
|-------------|----------------|
| Touch targets | 44px min-height on all value cards and stance buttons |
| Focus rings | `outline: 2px solid var(--accent); outline-offset: 2px` on all interactive elements — matches existing `.choiceBtn:focus-visible` |
| Keyboard navigation | Tab order: value cards (top to bottom), then stance Q1 options, then stance Q2 options, then submit. No custom tabIndex needed if DOM order matches layout order. |
| Screen reader: ranking state | Each value card button has `aria-pressed={isRanked}` and `aria-label="{value}, ranked {rankNumber}" (or "{value}, not yet ranked")` |
| Screen reader: stance selection | Stance button group uses `role="group"` with `aria-labelledby` pointing to the question text. Selected button gets `aria-pressed="true"`. |
| Screen reader: disabled stance section | Stance container has `aria-disabled="true"` while gated. The instruction copy "Finish ranking your values to continue." is visible text — no aria-live needed. |
| Error announcement | Error message element uses `role="alert"` so screen readers announce it on appearance |

Source: WCAG 2.5.5 (touch target), WCAG 4.1.2 (name, role, value), existing `.choiceBtn:focus-visible` pattern.
