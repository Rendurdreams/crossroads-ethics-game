**A. Extend `computeProfile(choiceHistory)` to return 4 new fields alongside existing `dominant`, `counts`, `leastUsed`:**

1. **`trajectory`** — object `{ early: string|null, late: string|null, shifted: boolean }`:
   - Split choiceHistory by `entry.round`: early = rounds where `round <= 2`, late = rounds where `round >= 5`
   - For each half, compute weight-adjusted dominant framework (per D-07): each framework tag in a choice counts `entry.moral_weight` times (default 1 if missing). Find the framework with highest weighted count. If total weighted count is 0 for that half, return `null`.
   - `shifted = early !== null && late !== null && early !== late`
   - If fewer than 1 entry in early OR late, set that half to `null`

2. **`consistency_score`** — string `'high'|'low'|null`:
   - Use unweighted framework counts (existing `counts` object). Find max count and total. If total === 0 return `null`.
   - `ratio = maxCount / total`. If ratio >= 0.5, return `'high'`. Otherwise `'low'`.
   - This captures whether the player stuck primarily to one framework.

3. **`virtue_streak`** — number (longest consecutive rounds with a virtue-tagged choice):
   - Sort choiceHistory by `entry.round` ascending
   - Walk through, incrementing a counter when `(entry.frameworks ?? []).includes('virtue')`, resetting to 0 otherwise. Track max.

4. **`virtue_heavy_count`** — number (virtue choices in heavy-weight rounds):
   - Count entries where `entry.moral_weight === 3` AND `(entry.frameworks ?? []).includes('virtue')`

Return signature becomes: `{ dominant, counts, leastUsed, trajectory, consistency_score, virtue_streak, virtue_heavy_count }`
