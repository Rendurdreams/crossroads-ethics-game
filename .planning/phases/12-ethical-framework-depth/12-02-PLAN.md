**C. Log dismissal flags on choice submission (per D-18):**

In the existing `handleChoice` function, when inserting to the `choices` table, the schema does not have metadata columns. Instead, track awareness prompt data in local state that will be assembled into player data during endSession. Since endSession runs in Host.jsx (not Play.jsx), the simplest no-migration path is:

1. After a choice is submitted for a round where the prompt was shown, update the player's `debrief_context` or `choice_history` via a Supabase update on the player row. Add this after the existing choice insert in `handleChoice`:

   ```javascript
   // Log awareness prompt flags if applicable
   if (promptShownRounds.has(session.current_round)) {
     const wasPromptDismissed = promptDismissedRounds.has(session.current_round)
     // Append to player's choice_history metadata via a lightweight update
     // This data will be available when endSession reads player data
     await supabase.from('players').update({
       awareness_log: [
         ...(player?.awareness_log ?? []),
         {
           round: session.current_round,
           awareness_prompt_shown: true,
           awareness_prompt_dismissed: wasPromptDismissed
         }
       ]
     }).eq('id', playerId)
   }
   ```

   This stores the awareness log as a JSONB field on the player row — no schema migration needed since Supabase Postgres accepts arbitrary JSONB keys on existing JSONB columns. The `players` table accepts this because the update sets a new top-level key.

   IMPORTANT: This must run AFTER the choice insert succeeds, not before. Do not block the choice insert on this secondary update. Use `.then()` or a separate await after the primary insert.
