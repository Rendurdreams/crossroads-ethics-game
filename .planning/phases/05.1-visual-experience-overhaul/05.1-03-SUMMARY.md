# Phase 05.1 Plan 03: Framer Motion Transitions + Atmosphere Tint Summary

## One-Liner

Cinematic Framer Motion page transitions, round-to-round fade-through in Play.jsx, staggered FrameworkProfile reveal, --atmosphere-warmth CSS var driven by worldState, and glass card wrappers on ConsequenceReveal/ContentNote.

## What Was Built

### Task 1: Framer Motion page transitions on all 4 pages + atmosphere tint

All four page components (Landing, HostSetup, Host, Play) now wrap their outermost returned element with `motion.div` using shared `pageVariants` (opacity 0→1 on enter, 0.4s ease-out; opacity 1→0 on exit, 0.25s ease-in). Every page calls `useReducedMotion()` and passes empty variants when the user prefers reduced motion.

Play.jsx additionally wraps game content areas with `AnimatePresence mode="wait"` and an inner `motion.div` keyed on `round-${session.current_round}-${session.status}`. This fires the cinematic fade-through (0.3s exit, 0.35s hold, 0.4s enter) when:
- The round number increments (next round)
- The status changes within a round (active → round_complete)

The reflection section in the finished view uses a standalone `motion.div` with `opacity: 0, y: 12` → `opacity: 1, y: 0` and a 0.8s delay, replacing the CSS animation-delay that Plan 02 removed.

Host.jsx and Play.jsx compute `warmth` (0.0–1.0) from `worldState` and write it as `--atmosphere-warmth` inline style on the page-level motion.div wrappers. Landing and HostSetup use neutral 0.5 since they lack worldState access.

### Task 2: FrameworkProfile stagger + ConsequenceReveal/ContentNote glass wrappers

FrameworkProfile.jsx replaces the four CSS `animation-delay` rules with Framer Motion `staggerChildren: 0.25` on the outer `motion.div` wrapper. Each section (sectionCard, conflictSection, leastUsedSection, choiceLog) is now a `motion.div` with `sectionVariants` (opacity 0, y:12 → opacity 1, y:0, 0.5s ease-out). When `shouldReduce` is true, both container and section variants are collapsed to empty objects.

FrameworkProfile.module.css had its `opacity: 0; animation: fadeUp ...; animation-delay: Xms` rules removed from all four sections. The `@keyframes fadeUp` definition was also removed — Framer Motion is now the single animation authority for this component.

ConsequenceReveal.jsx wraps the consequence text, framework wrapper, and meters wrapper in a `<div className={styles.card}>`, floating the content over the ambient gradient as a glass surface. ContentNote.jsx wraps the header, note text, and buttons in a `<div className={styles.card}>`.

Both CSS files received a new `.card` rule with the full glass-morphism recipe: `var(--glass-bg)`, `backdrop-filter: blur(var(--blur-glass))`, `var(--glass-border)`, and the standard box-shadow stack.

## Decisions Made

| Decision | Rationale |
|----------|-----------|
| roundKey includes both current_round and status | Per RESEARCH.md Pitfall 5 — without status in key, transition doesn't fire at round close, only at round advance. The dramatic moment (consequence reveal) would appear instantly. |
| computeWarmth helper inline in Host.jsx and Play.jsx | worldState not available at App.jsx level without context or prop-drill. Landing/HostSetup use 0.5 neutral. No new context layer needed. |
| .card CSS added here (not waiting for Plan 02) | Plan 02 is a parallel agent — its .card additions would land on a different branch. If this plan deferred the .card class, the JSX would reference styles.card with no visual effect (no error, but no glass). |
| @keyframes fadeUp removed from FrameworkProfile.module.css | Now unused — Framer Motion handles all entrance animations for these sections. Leaving it would be dead CSS. |
