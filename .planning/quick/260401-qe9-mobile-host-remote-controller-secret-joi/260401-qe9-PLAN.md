## Architecture Overview

```
COMPUTER (big screen, projected)          PHONE (Jay's hand)
┌──────────────────────────┐    ┌──────────────────────────┐
│  Host.jsx                │    │  HostRemote.jsx (NEW)    │
│  - Animated map          │    │  - Start / Close / Next  │
│  - Vote tallies          │    │  - Timer controls        │
│  - Lesson overlay        │    │  - Player "why" answers  │
│  - Research baseline     │    │  - Live vote count       │
│  - NO control buttons    │    │  - Skip round            │
│                          │    │  - End game              │
│  Listens to Supabase     │    │  Mutates Supabase        │
│  + broadcast channel     │    │  + broadcast channel     │
└──────────────────────────┘    └──────────────────────────┘
         ▲                              │
         │      Supabase real-time      │
         └──────────────────────────────┘
```

Both subscribe to the same channels. The remote performs mutations; Host.jsx reacts to them. A new broadcast channel `remote:{sessionId}` handles settings changes (timer adjustments) that Host.jsx picks up.

**Lobby View (session.status === 'lobby'):**

- "START GAME" button (disabled if < 1 player)

**Active Round View (session.status === 'active'):**
- Round X of Y
- Scenario title
- Timer display (large, prominent)
- Votes: X of Y submitted
- Controls:
  - **CLOSE ROUND** button
  - **+30s** button (extends timer via broadcast to Host.jsx)
  - Timer preset buttons: 30 / 45 / 60 / 90 / 120 (sets timer for NEXT round)

**Round Complete View (session.status === 'round_complete'):**
- Vote breakdown (% per choice)
- Player "why" answers (fetch from choices table or broadcast)
- Controls:
  - **NEXT ROUND** button
  - **SKIP ROUND** button (advances current_round by 2 instead of 1)
  - **END GAME** button (if last round or anytime)

**Finished View:**
- "Session complete" confirmation
- Group stats summary

**Control Functions:**
All mutations are direct Supabase calls (same as Host.jsx):
- `startGame()` — UPDATE sessions SET status='active', current_round=1
- `closeRound()` — compute world state, UPDATE sessions SET status='round_complete', world_state
- `nextRound()` — UPDATE sessions SET status='active', current_round+1
- `endSession()` — compute profiles, UPDATE players + sessions
- `extendTimer()` — broadcast on `remote:{sessionId}` channel: `{ event: 'extend_timer', payload: { seconds: 30 } }`
- `setNextTimer(duration)` — broadcast: `{ event: 'set_timer', payload: { duration } }`
- `skipRound()` — same as nextRound but increments by 2

**Import shared logic:**
- `applyChoicesToWorld` from worldState.js
- `computeProfile`, `findConflicts`, `findMoralConflicts` from detection.js
- `getScenarioByRound`, `getPlayableScenarios` from scenarios.js
- `getBreakFlagForChoice` from breakFlags.js

### Task 5: Timer Sync
Currently the timer runs in Host.jsx via `setInterval` + `dispatch('TICK')`. With the remote:
- **Timer still runs in Host.jsx** (it has the interval + broadcast to players)
- Remote sends `extend_timer` → Host.jsx adds seconds
- Remote sends `set_timer` → Host.jsx updates `timerDuration` for next round
- Remote displays timer by listening to the same `timer:{sessionId}` broadcast that players receive
- This means Host.jsx MUST still be open on the computer. The remote is a controller, not a replacement.

**For closeRound / endSession:**
These involve heavy computation (world state, player profiles). Two options:
- **Option A:** Remote does the computation (duplicates Host.jsx logic)
- **Option B:** Remote broadcasts a command, Host.jsx executes it

**Decision: Option A.** The remote imports the same functions and does the computation directly. This makes the remote self-sufficient — if the host screen crashes, the remote still works. Host.jsx picks up the changes via its session subscription.

**BUT:** Timer broadcasting still requires Host.jsx. If Host.jsx is not open, players don't see the countdown. Solution: HostRemote.jsx ALSO broadcasts timer ticks when it detects Host.jsx isn't broadcasting (fallback). Check: if no timer broadcast received in 3 seconds while timer should be running, remote takes over broadcasting.
